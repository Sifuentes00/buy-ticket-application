### Тип приложения
Разрабатываемая система является **клиент-серверным веб-приложением** с REST API.  
Frontend — многостраничное приложение на React, Backend — REST сервис на Spring Boot. Система использует централизованную аутентификацию через Keycloak.

### Стратегия развёртывания
Вид развертывания - распределенное.
Система развёртывается в виде набора **Docker-контейнеров**:

- **Frontend**: React-приложение (Vite)  
- **Backend**: Spring Boot REST API  
- **Аутентификация**: Keycloak  
- **База данных**: PostgreSQL  

Каждый компонент независим и может масштабироваться отдельно. Контейнеризация упрощает развертывание и поддержку, а также позволяет легко масштабировать отдельные части системы.

### Показатели качества

- **Масштабируемость**: возможность увеличивать количество экземпляров frontend и backend без изменений архитектуры  
- **Безопасность**: централизованная аутентификация через Keycloak, поддержка ролей и токенов JWT  
- **Производительность**: минимальная нагрузка на фронтенд, эффективные REST-запросы к backend  
- **Поддерживаемость**: чёткое разделение слоёв Controller → Service → Repository → Entity  
- **Расширяемость**: новые функциональные модули интегрируются через сервисный слой без изменения базовой структуры  

### Сквозная функциональность

- **Аутентификация и авторизация**: Keycloak + JWT, применяется ко всем защищённым endpoint  
- **Логирование**: централизованное логирование всех сервисов и контроллеров backend  
- **Обработка ошибок**: глобальный обработчик исключений в Spring Boot  
- **Валидация данных**: осуществляется на уровне DTO и контроллеров

### Сравнение и улучшения

![Вывод](https://github.com/Sifuentes00/buy-ticket-application/blob/main/docs/ClassDiagrams/result.png) 

**Причины отличий:**  
- MVP реализации для первого спринта  
- Ограничение времени на разработку  
- Отсутствие необходимости полного разделения слоёв на этапе прототипа  

**Пути улучшения:**  
- Ввести DTO и мапперы для отделения модели от API  
- Централизовать обработку ошибок и логирование  
- Чётко разделить Controller и Service для соблюдения принципов SOLID  
- Улучшить интеграцию Keycloak с использованием фильтров и AOP  
- Рассмотреть применение архитектурных шаблонов Layered и MVC  

### Вывод

- Идеальная архитектура обеспечивает высокую поддерживаемость, безопасность и масштабируемость  
- Реальная архитектура соответствует To Be в основном, но требует рефакторинга слоёв, введения DTO и централизованного логирования  
- После внесения улучшений система станет более поддерживаемой, расширяемой и безопасной
