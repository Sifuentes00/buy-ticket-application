## Введение

Данный документ описывает план тестирования веб-приложения ["TicketPro"](https://github.com/Sifuentes00/buy-ticket-application). Документ предназначен для тестировщиков и разработчиков, проводящих проверку данного проекта. Цель тестирования - проверка соответствия реального поведения программы проекта и ее ожидаемого поведения, которое описано в [требованиях](https://github.com/Sifuentes00/buy-ticket-application/blob/main/docs/SRS.md).

<a name="items"/>

## Объект тестирования

В качестве объектов тестирования можно выделить следующие функциональные требования:

* Регистрация нового пользователя;
* Вход в систему (пользователь / администратор);
* Просмотр списка фильмов;
* Просмотр подробной информации о фильме;
* Просмотр и управление отзывами;
* Просмотр доступных сеансов;
* Покупка билета зарегистрированным пользователем;
* Управление фильмами (добавление, редактирование, удаление) — для администратора;
* Управление сеансами — для администратора;
* Выход пользователя из учетной записи;
* Просмотр истории покупок.

<a name="quality"/>

## Атрибуты качества

1. Функциональность:
    - функциональная полнота: приложение должно предоставлять все заявленные функции работы с фильмами, отзывами, сеансами и билетами;
    - функциональная корректность: каждая функция должна выполнять своё действие корректно.
2. Удобство использования:
    - интерфейс должен быть понятным, все кнопки и поля имеют логичные названия;
    - все страницы должны соответствовать предоставленным мокапам.
3. Безопасность:
    - доступ к покупке билетов открыт только авторизованным пользователям;
    - администрирование доступно только администратору.
    - пароль администратора и пользователей не должен быть доступен другим лицам.
4. Доступность:
    - Интерфейс должен корректно отображаться на всех популярных десктопных размерах.

<a name="risk"/>

## Риски

В данном случае к рискам можно отнести:
* недоступность базы данных MySQL или ошибки соединения;
* Потеря данных при одновременном бронировании одних и тех же мест различными пользователями;
* Некорректная работа интерфейса из-за медленной загрузки данных;
* Ошибки при валидации данных пользователя (имя, email, пароль);
* Ошибки в логике прав администратора и обычного пользователя.

<a name="features"/>

## Аспекты тестирования

В ходе тестирования планируется проверить реализацию основных функций приложения. Аспекты, подвергаемые тестированию: 
* Регистрация пользователя;  
* Вход пользователя; 
* Просмотр списка фильмов;
* Просмотр подробной информации о фильме; 
* Оставление отзыва;
* Покупка билета;  
* Администрирование фильмов;
* Администрирование сеансов;
* Просмотр купленных билетов;
* Выход из системы.

### Регистрация пользователя
Этот вариант использования небходимо протестировать на:
* ввод корректных данных;
* ввод пустых данных;
* отмена регистрации;

### Вход пользователя
Этот вариант использования небходимо протестировать на:
* вход с корректными логином и паролем; 
* вход с неверным паролем. 

### Просмотр списка фильмов
Этот вариант использования небходимо протестировать на:
* успешная загрузка каталога фильмов;
* реакция интерфейса при отсутствии данных.  

### Просмотр подробной информации о фильме
Этот вариант использования небходимо протестировать на:
* отображение описания, жанра, актёров, отзывов;
* отображение списка сеансов;
* корректное поведение для гостей и зарегистрированных пользователей;
* переход к окну покупки билета.

### Оставление отзыва
Этот вариант использования небходимо протестировать на:
* доступность функции только для зарегистрированного пользователя;
* корректность добавления нового отзыва;

### Покупка билета
Этот вариант использования небходимо протестировать на:
* открытие схемы зала;
* выбор места;
* попытка выбрать место, которое уже занято;
* успешная покупка;
* появление билета в «Моих билетах».

### Администрирование фильмов
Этот вариант использования небходимо протестировать на:
* добавление нового фильма;
* редактирование параметров фильма;
* удаление фильма;
* реакция системы при неполных данных.

### Администрирование сеансов
Этот вариант использования небходимо протестировать на:
* добавление сеанса;
* изменение даты/времени;
* удаление сеанса;
* реакция системы при неполных данных.

### Просмотр истории покупок
Этот вариант использования небходимо протестировать на:
* корректное отображение купленных билетов;

### Выход из системы
Этот вариант использования небходимо протестировать на:
* выход из профиля;
* возврат на главное окно;

## Нефункциональные требования:
* соответствие всех элементов интерфейса мокапам;
* читаемость текста;
